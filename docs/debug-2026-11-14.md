### 问题 3 复核：参考项目 COM 路线已核对；前端坐标已统一，后端根因未消除

- 参考项目 `dib/shell.py` 实测做法（与旧记录一致，补 vtable 槽位号）：
  - `Shell.Windows.FindWindowSW(SWC_DESKTOP)` → `IServiceProvider` → `IShellBrowser`
    → `QueryActiveShellView` → `IFolderView` / `IFolderView2`；
  - 排列开关：IFolderView2 slot 24 `SetCurrentFolderFlags(mask, value)`、slot 25
    `GetCurrentFolderFlags()`；`ARRANGE_MASK = FWF_AUTOARRANGE(0x1) | FWF_SNAPTOGRID(0x4)`；
  - 搬图标：slot 16 `SelectAndPositionItems(count, pidls, points, SVSI_POSITIONITEM)`，
    一次 Shell 调用批量搬；
  - 进程 DPI 感知、虚拟屏/显示器几何快照、退出后回读校验位置与标志位。
- 本轮前端已修：摆位与逐帧同步统一用开局返回的 ListView 屏幕原点
  （`layout.areaX/areaY`，存 `originRef`），不再混用 `window.screenX/screenY`；
  已入袋图标不再参与逐帧同步；图标左上角偏移按真实格子半尺寸（`halfX/halfY`），
  不再用半径近似。
- **未消除的根因**：后端仍是 ListView 消息路线（`LVM_SETITEMPOSITION` + 改
  `GWL_STYLE` / 扩展样式位）。Win11 现代 Explorer 的自动排列/网格吸附由
  IFolderView2 标志位控制，ListView 样式位关不掉，图标被搬走后立刻吸回网格，表现就是
  「打不动」；部分系统上 `LVM_SETITEMPOSITION` 本身不被采纳。要彻底解决需要按参考项目
  补 Shell COM 后端（IFolderView2 读/写标志位 + `SelectAndPositionItems` 批量搬移 +
  退出回读校验），LVM 消息留作兜底分支。该改动较大且本机无法实机验证，待确认后实施。

## 问题 2：关系插件「表面能用，实机不通」——运行逻辑与故障点

### 完整链路（现状代码）

1. **配对**：一方 `generatePairCode()` 生成 6 位码（去掉 0/O/1/I），存 localStorage
   `maltese-relationship:pair`；另一方输入同一码（统一转大写）。
2. **频道与密钥派生**（`src/plugins/relationship/pairing.ts`，纯前端 WebCrypto）：
   - 频道名 = `maltese-rel-` + `sha256("maltese-relationship:" + 码)` 前 24 位 hex；
   - 消息密钥 = `sha256("maltese-relationship-key:" + 码)`；
   - 每条消息：随机 12B iv，密钥流 = 逐块 `sha256(key ‖ iv ‖ "#n")`，明文 JSON XOR 后
     base64，信封 `{v:1, iv, data}`。中继只看到密文。
3. **发送**（前端 → Rust `relay_publish` → ntfy.sh）：
   `POST {base}/{topic}`，body 是加密信封；默认中继 `https://ntfy.sh`，可被
   localStorage `maltese-relationship:relay` 覆盖。
4. **接收**：每 3 秒 `relay_fetch`，`GET {base}/{topic}/json?poll=1&since=<最后时间戳|all>`，
   按行解析 ntfy JSON，只取 `event=message`，前端用同一把密钥解密；按 `sid` 去重自己发的，
   按消息 id 去重聊天记录。
5. **消息类型**：`hello`（报名字/上线）、`relation`（关系选择）、`chat`（聊天）、`bye`（下线）。
6. 后端 `src-tauri/src/relay.rs` 只做 HTTP 收发，不碰明文；命令已在 `lib.rs:4101-4102` 注册。

### 已定位的代码级故障点

- **A. 加入方首条 hello 发不出去（stale closure，确定的 bug）**
  `join()` 先 `savePair({code,...})` 再 `await send({t:"hello"})`；而 `send` 的
  useCallback 闭包捕获的是旧 `pair.code`（此时仍是空串），`send` 开头
  `if (!code) return false`，hello 直接被吞，界面却不报错。后续聊天在重渲染后才可能发出，
  但「对方已连接」永远不会亮。
- **B. 中继请求不走系统代理（确定的薄弱点）**
  `relay.rs` 的 `reqwest::Client::builder()` 没配代理；`Cargo.toml` 里 reqwest
  `default-features = false`，proxy 特性也没开。机器若走 Clash/系统代理上网，浏览器通而
  Rust 直连 ntfy.sh 失败。`lib.rs:2115` 已有 `get_updater_proxy()`（先环境变量后读注册表
  `Internet Settings`）可复用。
- **C. ntfy.sh 在国内网络可达性**：本机直连 `ntfy.sh` HTTP 200、0.84s，发布/拉取格式验证
  正常；但实机若网络受限或被限流，3 秒轮询会报「连接中断」。中继地址目前只存在
  localStorage，界面上没有可改的入口。
- **D. 次要：发起方不会主动回 hello**。加入方发 hello 后，发起方要等自己发一条（关系/聊天）
  对方才看得到上线；建议加入后双方都补发一次 hello。
- **E. 待实机验证**：WebView2 非安全上下文里 `crypto.subtle` 是否可用（本项目其它地方没
  用过 WebCrypto）。若不可用，加密会抛错，前端 catch 后状态栏应显示「发送失败」。

## 问题 3：台球开局后，被击打的图标不移动（对照参考项目）

### 现状实现（`desktop_icons.rs` + `Billiards.tsx`）

- 开局 `desktop_icons_begin_game`：找桌面 ListView → `LVM_GETITEMCOUNT` → 跨进程
  `OpenProcess`/`VirtualAllocEx`/`ReadProcessMemory` 发 `LVM_GETITEMPOSITION` 读原始位置，
  写备份文件 + 内存；`relax_styles` 清 `LVS_AUTOARRANGE(0x0100)` 与
  `LVS_EX_SNAPTOGRID(0x00080000)`。
- 逐帧：40ms 一次 `desktop_icons_move`，屏幕坐标 → `ClientToScreen` 原点减成客户区坐标，
  打包 `(y<<16)|x` 发 `LVM_SETITEMPOSITION`。
- 前端物理：三角摆阵、白球/目标球碰撞、摩擦/反弹/入袋；摆位用 `layout.areaX/areaY`，
  逐帧同步用 `window.screenX/window.screenY`（两套坐标基准，单屏底部任务栏时重合，
  顶部/侧边任务栏或多屏会错位）。

### 参考项目怎么做（`dib/shell.py`，关键差异）

- **不用 ListView 消息**：README 明确写「no Explorer injection, ListView message patching」。
  全部走文档化 Shell COM：`Shell.Windows.FindWindowSW(SWC_DESKTOP)` → `IServiceProvider`
  → `IShellBrowser` → `QueryActiveShellView` → `IFolderView` / `IFolderView2`。
- **排列开关在 IFolderView2 标志位**：`ARRANGE_MASK = FWF_AUTOARRANGE(0x1) | FWF_SNAPTOGRID(0x4)`，
  通过 IFolderView2 vtable slot 24/25 读/写；我们改的是 ListView 窗口样式位，现代 Explorer
  桌面视图未必认这一套——自动排列没真正关掉，图标被 `SETITEMPOSITION` 后立刻吸回网格，
  视觉上就是「打不动」。
- **搬图标的官方接口**：`IFolderView2.SelectAndPositionItems`（vtable slot 16），按 PIDL
  批量传 POINT，一次 Shell 调用搬完；我们是逐条 `LVM_SETITEMPOSITION` 消息。
- 参考项目还做了：进程级 DPI 感知、几何（虚拟屏/显示器数）变化检测、移动边界校验、
  恢复后回读校验位置与标志位是否真的复位。

### 候选根因（按可能性排序）

1. **自动排列/吸附网格没被真正关掉**（最可能）：只改 ListView 样式位，Explorer 实际仍按
   IFolderView2 标志吸附，图标移动后瞬间回弹。表现为开局摆阵也会被吸回、击打后看不出位移。
2. **`LVM_SETITEMPOSITION` 在 Win11 桌面视图不被采纳**：参考项目正是因此改用 COM 接口。
3. **坐标基准不一致**：逐帧 `window.screenX/Y` 与摆位 `layout.areaX/Y` 混用，顶部/侧边
   任务栏、多显示器场景图标会飘到错误位置。
4. DPI 缩放未对齐：线程 DPI 感知上下文与 Explorer 不一致，坐标被缩放。

### 建议修复方向（待确认后本地实施）

- 后端增加 Shell COM 后端（IFolderView2：读标志位关自动排列/网格、`SelectAndPositionItems`
  批量搬移、退出还原标志位并回读校验）；LVM 消息作为兜底分支保留。
- 前端统一坐标基准：都用开局返回的 ListView 屏幕原点，不再混用 `window.screenX/Y`。
- 补 DPI 感知与多屏/几何变化检测；崩溃兜底还原逻辑保留现有备份文件方案。
