诊断（子 agent 只读分析 + 复核代码）确认两个根因，均已修：

| # | 根因 | 位置（修复前） | 修复 |
| --- | --- | --- | --- |
| 1 | 「跟随状态」模式下同一情境**只说一次**：`if (state.firedFor === situation) return;`，而情境 key 只有 `kind|playing|away` 三要素。连着一下午写代码 = 同一情境 → 说完第一句后永久静默，直到切程序/切歌/离开 | `src/App.tsx` 主动聊天 tick | 删掉一次性锁，改为只受冷却时间约束（冷却/每小时上限仍在） |

顺带修掉的放大因素：

- `overHourlyLimit` 把**未来时间戳**也算进 1 小时窗口（`now - time < 1h` 对负数成立），系统时钟跳过就会把额度锁死 → 过滤 `time <= now`，并在读取时清掉未来值；
- `recordSpeakTime` 在「是否真的弹出去」判断**之前**调用 → 模型慢/面板被点开也会白吃一次额度 → 移到可见性判断之后；
- 0% 档 UI 承诺「不主动开口」但代码仍会每 240 分钟说一次 → 加 `if (plan.level <= 0) return;`；
- 独立设置窗口的滑块没写 `maltese-proactive-level` → 补 `saveProactiveLevel(value)`。

## 2. 启动时界面显示不全（偶发）

根因：**窗口 show 的时刻早于 WebView2 真正绘制完这一帧**。整条 show 链（前端 `showReadyIsland` → 后端 `show_island`）没有任何「已绘制」判据，而窗口是 `visible:false` 创建的，隐藏期间浏览器不一定做呈现；亮出来的是尚未合成的表面。鼠标移入会触发新的 damage 从而补全，这就是「过一会儿/动一下就恢复」。

修法（`src/App.tsx`）：

- 新增 `waitForFirstPaint()`：等 2 帧 rAF + `document.fonts.ready`，整体最多 400ms；**末尾那次 rAF 带 120ms 超时**（隐藏窗口里 rAF 可能不回调，无超时会把 show 永久挂起）；
- 新增 `waitForPetGif()`：show 前等当前桌宠 GIF `decode()`，最多 300ms（透明窗口下 GIF 没解码就是一块空白）；
- `showReadyIsland()` 里先 `await Promise.all([waitForFirstPaint(), waitForPetGif()])`，再 `invoke("show_ready_island")`。

仍未做（诊断建议、本机风险较高，留待单独验证）：`apply_stage_geometry` 把 `set_size` + `set_position` 合并成一次原子调用、show 后 `is_visible()` 校验重试、首帧前禁用 CSS 过渡（`maltese-booting`）。
