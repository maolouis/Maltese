## B1 设置打不开

### 现象

三个入口（展开面板顶部「设置」、快捷面板右上「设置」、托盘「配置桌宠」）点了都没反应。
实机枚举能看到设置窗口的 HWND：标题 `Maltese · 桌宠设置`、外部矩形 `576×819`、
`IsWindowVisible=False`，其 WebView2 子窗口只有 `WRY_WEBVIEW(560×780, visible=False)`
和 `Chrome_WidgetWin_0`（尺寸 `0×0`），**没有** `Chrome_WidgetWin_1` /
`Chrome_RenderWidgetHostHWND`；同一时刻主窗口、懒创建的 `bongo-pet` 都有完整子链。
即「窗口创建成功，但 WebView2 控制器从未初始化完，`show()` 也没真正生效」。

### 根因

`c327044` 把设置窗口从 `tauri.conf.json` 的**启动期创建**改成 `window_factory::ensure`
的**运行时懒创建**，而调用它的 `open_settings_window` 是**同步命令**。

Windows 下 Tauri 的同步命令跑在主线程的 WebView2 消息派发栈里；
`tauri-runtime-wry` 的 `send_user_message`（`tauri-runtime-wry-2.11.4/src/lib.rs:235`）
发现当前线程就是主线程时不再排队，而是**就地**执行 `create_window`。wry 建 WebView2
要跑嵌套消息泵（`wry-0.55.1/src/webview2/mod.rs` 的 `create_controller` →
`webview2_com::wait_with_pump`），嵌套在 WebView2 自己的回调栈里就永远收不到完成回调：
HWND 建出来 → 控制器没建完 → 不能 show、子窗口 0×0。

为什么以前不坏：`c327044` 之前 settings 窗口在 `tauri.conf.json` 里预声明、启动期由
Tauri 正常创建，`open_settings_window` 只是 `get_webview_window("settings")` + `show()`。
懒加载后「创建」第一次落到了主线程同步调用栈里，旧参数（label/title/url/560×780/
min 460×560/resizable/center/visible）逐项核对过与新配方一致，所以不是参数问题。
Tauri 自己对 `WebviewWindowBuilder` 的 Known issues 也写明：Windows 下同步命令/事件
回调里建窗口会死锁，应当用 `async` 命令或独立线程（wry#583）。

### 修法

- `src-tauri/src/lib.rs`
  - `open_settings_window` 改为 `async fn`（Tauri 把 async 命令放到异步运行时线程，
    建窗口消息排进事件循环，与启动期窗口同一条正常路径）；并在创建前后打日志
    `settings window ready in ... (created/already visible)`，重复点击只剩聚焦。
  - `show_pet_bubble` / `resize_pet_bubble` / `open_billiards_window` /
    `pin_page_to_desktop` 同样是懒创建窗口的入口，一并改 `async`。
  - 托盘菜单「配置桌宠」事件在主线程触发，改成 `tauri::async_runtime::spawn`
    里再 `await open_settings_window(...)`，不再在主线程同步建窗口。
- `src-tauri/src/translation.rs`：`toggle_translation_window` 拆成「`async` 命令
  + 同步实现 `toggle_translation_window_sync`」，快捷键窗口线程（非主线程）继续直接
  调同步实现。
- `src-tauri/src/plugins.rs`：`open_plugin_window` 改 `async`。
- `src-tauri/src/window_factory.rs`：`ensure` 文档补充**线程要求**（禁止主线程调用），
  避免以后再踩。
- `src/App.tsx:5775`：快捷面板打开失败提示原本指向已经不存在的「桌宠右键菜单」，
  改成「请从托盘菜单「配置桌宠」再试一次」（对应验收 B1-09）。

### 回滚

`git revert <B1 commit>`；只动窗口创建/打开命令签名，回滚不牵连 `tauri.conf.json`
（本次没有改它）。

## B2 气泡点开后小狗会移动

### 现象

悬停互动面板 / 云朵消息浮层打开或关闭后，主窗口矩形变化，小狗在屏幕上偏移；
关掉气泡回不到原位，反复开合会累积漂移；严重时窗口停在浮层尺寸、狗槽被窗口边裁掉。

验收口径（[bug-acceptance-2026-11-17.md](bug-acceptance-2026-11-17.md) 第 2 节）：
设打开前 `R0`、完全展开 `R1`、关闭稳定 500ms 后 `R2`；面板在右时 `R1.left == R0.left`，
在左时 `R1.right == R0.right`；`R2` 各边与 `R0` 差 ≤2px；连续 10 次开合不累积。

### 根因

浮层几何有两条硬约束（见 [pet-overlay-geometry.md](pet-overlay-geometry.md)）：
**打开只改窗口宽高、不许移动小狗**；**前端「plan 拿方向 → flushSync 钉住小狗 →
set 一次性改矩形」两侧必须用同一份输入**。`c327044` 之后有三条路径破坏了它们：

1. **show 链路在浮层期间重排窗口。** `c327044` 给显示加了 `frontend_ready` 握手、
   `show_ready_island` 5×300ms 重试、第二实例 `show-request` 唤起，它们都会调
   `show_island`；旧实现不管窗口是否已经可见都重算一次收起态
   `apply_stage_geometry`。而 `apply_stage_geometry` 只在 `OVERLAY_SNAPSHOT` 已写入时
   才让路 —— 快照原本要等 `set_island_overlay` 才建，**plan → set 之间有空档**，
   这期间浮层已经按方向钉好、甚至窗口已经放大，一旦被收起态几何插队，小狗就被挪走。
2. **plan 与 set 各读一次窗口矩形。** 旧 `plan_island_overlay` 自己读
   `outer_position()` / `inner_size()` 算方向，`set_island_overlay` 再读一次算矩形；
   漫游动画未落定、拖拽收尾未落库时两次读数不同，方向就会算反 ——
   表现为开/关瞬间小狗跳一下（正是历史上反复出现的那类 bug）。
3. **拖拽收尾把放大后的窗口矩形存成狗位。** `start_island_drag` 的后台线程在松手时
   把 `window.outer_position()` 写进 `custom_position` 并 emit
   `island-position-changed`（前端持久化到 localStorage）。浮层打开时窗口矩形是
   「狗槽 + 面板」，左上角不再是狗位；这次拖拽如果在浮层期间收尾，错误坐标会被
   长期保存下来，之后每次 `apply_stage_geometry` 都按它摆位 —— 越开合越偏、
   关掉也回不去（对应 QA 在 LevelDB 里看到的多次 `focusd-island-position` 写入）。
   `set_island_overlay` 自身与 `apply_stage_geometry` 都有快照保护，但这段收尾逻辑
   以前没有任何保护。

### 修法

- `src-tauri/src/lib.rs`
  - 抽出 `create_overlay_snapshot()`：取消并等待位移动画落定 → 用窗口真实矩形
    （`outer_position` + `inner_size`，physical/scale 转逻辑）建快照 → 写回
    `custom_position`；建快照时置位 `OVERLAY_ACTIVE`（闲逛在空档里也不会动窗口）。
  - `plan_island_overlay` 改为**先钉快照、再算方向**（仍不改窗口矩形），
    `set_island_overlay` 直接复用同一份快照：两侧输入完全一致，「贴方向」和
    「改窗口」不可能再分叉；快照存在期间 `apply_stage_geometry` 一律不插队，
    顺带堵住 plan → set 的空档。
  - `show_island`：窗口已经可见时不再重算几何（与 `show_island_no_focus` 对齐），
    任何 show 链路（握手 / 补显 / 第二实例）都不会在浮层期间重排窗口。
  - `start_island_drag` 收尾：浮层已打开（有快照）或 mode 不是 collapsed 时
    **丢弃这次拖拽结果**，不写 `custom_position`、不 emit。
  - `set_island_overlay(None)`：先按快照原样恢复矩形；兜底新增「没有快照但窗口
    尺寸明显不等于收起态」时按收起态几何收回，修掉「关掉气泡后窗口停在浮层尺寸」。
  - 排障日志（验收 5.6）：`overlay plan (...)` 记方向/锚点/基准、`overlay open (...)`
    记新矩形、`overlay closed: restored rect ...` 记恢复后的位置。
- 回滚：`git revert <B2 commit>`。B2 只改 `src-tauri/src/lib.rs` 的浮层/显示/拖拽逻辑
  与文档，不牵连窗口创建参数。

cargo check（src-tauri）                          → exit 0（仅既有 warning）

## 8px 位移判定（睡眠缩边 → 唤醒后比锁角基线低 8px）

> 来源：`docs/delivery-verify-2026-11-17.md` 5.6 的待归因观察（10:54:08
> `focusd-island-position` 由 `{"x":2285,"y":1203}` 变成 `{"x":2285,"y":1211}`）。
> 本节给出代码级判定与最小修法；结论是**缺陷**，不是「贴 work_area 底边」的预期语义。

### 事实

- 机器 2560×1440，缩放 100%，收起大小 1.60× → 小狗槽 259×221
  （`slot_width_css` / `slot_height_css`，`lib.rs:3531-3539`）。
- 锁右下角（`lockCorner=br`）收起态基线：`x=2285, y=1203, w=259, h=221`。
- 10:54:02 睡眠缩边，y 动画到 1278（缩边公式 `lib.rs:3282-3291`）；
  10:54:02.865 合成鼠标唤醒；随后落位 `y=1211`，并被写进
  `localStorage["focusd-island-position"]`；此后一直停在 1211（下沿 1432）。

### 几何来源（代码依据）

| 路径 | 代码 | 锚点语义 |
| --- | --- | --- |
| 锁角 `lock_island_corner` | `lib.rs:1196-1237`（`MARGIN=16` @:1215、`work_area` @:1216、写 `custom_position` @:1226-1230） | **工作区四角 + 16px 边距**，结果存进 `custom_position` |
| 缩边 | `apply_stage_geometry` 的 `dog_tucked_y`（`lib.rs:3282-3291`） | 工作区底边 − 露头高度 − 狗在图内偏移 |
| 唤醒 | `apply_stage_geometry` → `resolve_stage_position`（`lib.rs:3317` / `3628-3639`） | `(Some(custom), false) => (custom.x, custom.y)`：**原样回到锁角基线** |
| 从未定位过（默认底中） | `dog_normal_y = work_bottom - slot_h_phys - physical_top_offset`（`lib.rs:3317`，`margin_y` 默认 0） | 工作区底边 − 狗槽，**没有 16px 边距** |
| 前端唤醒链路 | `App.tsx:1591-1602`（`restingAsleep` → `onSleepTuck`/`onSleepReveal`）、`:6733-6755`（`tuckIsland`/`revealIsland`）、`:6450-6488`（`syncNativeInteraction`）、`:8929-8953` | 只改 `isTucked`，自己不碰坐标 |
| 位置持久化 | `App.tsx:8879-8902`：监听 `island-position-changed` → `localStorage.setItem` | 只有 Rust 主动 emit 才会写 |
| Rust emit 点 | `lib.rs:1234`（锁角）、`lib.rs:544`（拖拽收尾） | **全仓仅这两处** |

### 结论：缺陷

1. **唤醒后应该落锁角基线（这次是 1203），不是 `work_bottom − 槽高`（1211）。**
   依据：`lockCorner` 的语义在 `lock_island_corner` 里就是「工作区边 + 16px 边距」，
   并且写进 `custom_position`；`resolve_stage_position` 对「有 `custom_position` 且未缩边」
   的分支只返回该坐标，根本不会重算 `dog_normal_y`。1211（= `1432 − 221`）只在
   「从来没定位过、没有 `custom_position`」的默认底中位才合法。
2. **1211 不是另一套公式算出来的「预期 8px」。** 同一时刻锁角公式给的是
   `1432 − 221 − 16 = 1195`；若工作区是满屏 1440（任务栏自动隐藏）则给 1203。
   两者都不等于 1211。全仓只有两处 emit，锁角不可能 emit 出 1211，
   所以这次写入只能来自**拖拽收尾**（`lib.rs:544`）。
3. **触发条件（旧代码缺陷）：** 改前的 `start_island_drag`（`lib.rs:439-468`）只拦
   「非收起态 / 缩边 / 已在拖」，**没有拦位移动画进行中**。缩边/唤醒动画
   （`POSITION_ANIMATION_DURATION = 320ms`，`lib.rs:97`）跑的时候窗口坐标是过渡值：
   一次「按下滑动 ≥3px」（前端阈值见 `App.tsx:1797-1819`）就会在动画中途开始拖拽 →
   把过渡帧写进 `custom_position`（`lib.rs:476-483`）→ 松手再写一次并 emit
   （`lib.rs:527-529` / `:544`）→ 前端持久化。
   1278 → 1203 的唤醒动画按 ease-out 第 31 帧（约 248ms）正好是 **1211**，
   与观测值逐像素吻合 —— 8px 就是这一帧离锁角基线还差的余量。
4. **影响不是一次性视觉抖动，而是持久化：** `custom_position` 与 localStorage 都被
   改成 1211，之后每次 `apply_stage_geometry` 都以它为基线，锁角语义被永久覆盖
   （直到用户再点一次「复位位置」或真的拖一次）。所以既不是「预期语义」，
   也不只是「位置可接受、只需修持久化」——**位置和持久化两处都要修**。

### 修法（最小改动，不动几何公式）

`src-tauri/src/lib.rs`：

1. 新增 `drag_start_allowed(state, animating)`（`lib.rs:439-452`）：**收起态 &&
   未缩边 && 未在拖 && 没有位移动画**才允许开始拖拽。`start_island_drag`
   改用它做闸门（`lib.rs:455-463`），动画中直接返回 —— 不写 `custom_position`、
   不 emit `island-position-changed`。动画只有 320ms，落定后再按一次即可；
   锁角模式下不跑闲逛（`App.tsx:7592` 已排除 `lockCorner`），所以这条闸门对锁角
   用户唯一的可见影响是「唤醒那 320ms 内按拖不生效」。
2. 拖拽收尾只在**真的移动过**时 emit：`final_position != drag_origin`
   （`lib.rs:535-546`）。零位移的「按下 → 松手」不再写 localStorage，
   锁角模式下不会用一次单击覆盖角落基线。
3. **不改** `apply_stage_geometry` / `resolve_stage_position` / `lock_island_corner`：
   唤醒回归锁角基线本来就是它们已有的语义（`resolve_stage_position` 的
