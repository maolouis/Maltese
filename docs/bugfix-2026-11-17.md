## B1 设置打不开

### 现象

三个入口（展开面板顶部「设置」、快捷面板右上「设置」、托盘「配置桌宠」）点了都没反应。
实机枚举能看到设置窗口的 HWND：标题 `Maltese · 桌宠设置`、外部矩形 `576×819`、
`IsWindowVisible=False`，其 WebView2 子窗口只有 `WRY_WEBVIEW(560×780, visible=False)`
和 `Chrome_WidgetWin_0`（尺寸 `0×0`），**没有** `Chrome_WidgetWin_1` /
`Chrome_RenderWidgetHostHWND`；同一时刻主窗口、懒创建的 `bongo-pet` 都有完整子链。
即「窗口创建成功，但 WebView2 控制器从未初始化完，`show()` 也没真正生效」。

### 根因

`c327044` 把设置窗口从 `tauri.conf.json` 的**启动期创建**改成 `window_factory::ensure`
的**运行时懒创建**，而调用它的 `open_settings_window` 是**同步命令**。

Windows 下 Tauri 的同步命令跑在主线程的 WebView2 消息派发栈里；
`tauri-runtime-wry` 的 `send_user_message`（`tauri-runtime-wry-2.11.4/src/lib.rs:235`）
发现当前线程就是主线程时不再排队，而是**就地**执行 `create_window`。wry 建 WebView2
要跑嵌套消息泵（`wry-0.55.1/src/webview2/mod.rs` 的 `create_controller` →
`webview2_com::wait_with_pump`），嵌套在 WebView2 自己的回调栈里就永远收不到完成回调：
HWND 建出来 → 控制器没建完 → 不能 show、子窗口 0×0。

为什么以前不坏：`c327044` 之前 settings 窗口在 `tauri.conf.json` 里预声明、启动期由
Tauri 正常创建，`open_settings_window` 只是 `get_webview_window("settings")` + `show()`。
懒加载后「创建」第一次落到了主线程同步调用栈里，旧参数（label/title/url/560×780/
min 460×560/resizable/center/visible）逐项核对过与新配方一致，所以不是参数问题。
Tauri 自己对 `WebviewWindowBuilder` 的 Known issues 也写明：Windows 下同步命令/事件
回调里建窗口会死锁，应当用 `async` 命令或独立线程（wry#583）。

### 修法

- `src-tauri/src/lib.rs`
  - `open_settings_window` 改为 `async fn`（Tauri 把 async 命令放到异步运行时线程，
    建窗口消息排进事件循环，与启动期窗口同一条正常路径）；并在创建前后打日志
    `settings window ready in ... (created/already visible)`，重复点击只剩聚焦。
  - `show_pet_bubble` / `resize_pet_bubble` / `open_billiards_window` /
    `pin_page_to_desktop` 同样是懒创建窗口的入口，一并改 `async`。
  - 托盘菜单「配置桌宠」事件在主线程触发，改成 `tauri::async_runtime::spawn`
    里再 `await open_settings_window(...)`，不再在主线程同步建窗口。
- `src-tauri/src/translation.rs`：`toggle_translation_window` 拆成「`async` 命令
  + 同步实现 `toggle_translation_window_sync`」，快捷键窗口线程（非主线程）继续直接
  调同步实现。
- `src-tauri/src/plugins.rs`：`open_plugin_window` 改 `async`。
- `src-tauri/src/window_factory.rs`：`ensure` 文档补充**线程要求**（禁止主线程调用），
  避免以后再踩。
- `src/App.tsx:5775`：快捷面板打开失败提示原本指向已经不存在的「桌宠右键菜单」，
  改成「请从托盘菜单「配置桌宠」再试一次」（对应验收 B1-09）。
