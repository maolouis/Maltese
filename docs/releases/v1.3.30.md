# Maltese v1.3.30

## 修：快捷方式里的 cmd / PowerShell 脚本「点了没反应」

### 根因

v1.3.25 那轮把 `.bat` / `.cmd` / `.ps1` 从 `ShellExecuteW` 改成 `Command::spawn` + `CREATE_NO_WINDOW`，本意是「不弹黑框、直接跑完」。但主程序是 **windows 子系统（没有控制台）**，Rust 的 `Command` 会把父进程那套已经失效的标准句柄塞进 `STARTF_USESTDHANDLES`：

- 脚本进程根本没有控制台（实测 `GetConsoleWindow()` 返回 0）；
- `echo` / 报错输出无处可去；
- `pause`、`Read-Host` 立即 EOF。

于是脚本虽然「跑了」，用户却看不到任何窗口和输出——就是「跑不动」的体感。中途试过的 `CREATE_NEW_CONSOLE` 也不行：窗口会出来，但标准句柄被 NUL/管道占用，窗口是空的。

### 修法

脚本一律按**双击语义**启动，由系统创建带正确标准句柄的控制台窗口（新增 `shell_execute_program`，内部走 `ShellExecuteW`）：

| 类型 | 启动方式 |
| --- | --- |
| `.cmd` / `.bat` | `ShellExecuteW("open", "cmd.exe", "/d /c call "<脚本>"", 脚本目录)` |
| `.ps1` | `ShellExecuteW("open", "powershell.exe", "-NoProfile -ExecutionPolicy Bypass -File "<脚本>"", 脚本目录)` |
| `.py` | 先 `py.exe`，失败退回 `python.exe`，都不行再交给系统关联 |

每一档都保留 `shell_execute(脚本文件)` 兜底，避免某台机器上关联异常时彻底失败。

### 验证（从「无控制台」的 windows 子系统进程里实测）

用与正式代码相同的 `ShellExecuteW` 调用，从 `#![windows_subsystem = "windows"]` 的测试程序里启动脚本：

| 启动方式 | 脚本内自报 |
| --- | --- |
| 旧实现 `CREATE_NO_WINDOW` | `GetConsoleWindow()=0`、`windowWidth=none`、输出丢失 |
| 旧实现 `CREATE_NEW_CONSOLE` | 窗口存在但 `IsOutputRedirected=True`，窗口是空的 |
| **新实现 ShellExecuteW** | `redirectedOut=False`、`windowWidth=120`，`.cmd` 与 `.ps1` 都能写文件、能看到窗口 |
