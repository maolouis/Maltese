# Maltese v1.3.18

## 修 1.3.17 的回归：面板展开到反方向

v1.3.17 里我在前端留了一段「本地预判方向」的兜底：用 `window.screenX` / `screen.availWidth` 自己算面板该往哪边长。它和原生算法的输入不完全一致（窗口坐标 vs 小狗槽坐标、显示器工作区 vs 屏幕宽度），算出「右」而原生决定「左」时，小狗会被钉到错误的一侧、面板就展开到了反方向——比闪一下更明显。

这一版把本地预判整段删掉，方向只有一个来源：

1. `plan_island_overlay(mode)` 由原生用**和真正展开完全相同**的输入（小狗槽锚点、槽尺寸、显示器工作区）算出 side / vertical，不改窗口。
2. 前端拿到后用 `flushSync` **同步提交**：先上 `island--overlay-{side}` / `--overlay-below` 类，把小狗钉到正确角上（此时窗口还是原尺寸，画面不变）。
3. 提交完成后再调用 `set_island_overlay`，由原生一次 `SetWindowPos` 同时改尺寸和位置。

因为方向和几何都出自同一份原生计算，不会再出现「小狗钉左边、窗口往左长」或反过来的错位帧；面板方向也回到正确一侧。

顺带把方向状态提升到外层，收起浮层时清空，避免下一次打开沿用上一轮的方向。
