# 刷视频与小狗自媒体账号重构说明

## 调研结论

“大肥鱼”类项目的共同结构是定时唤醒、读取状态、模型决策、调用工具、写回记忆，再等待下一轮。桌宠只是状态呈现，平台账号、浏览器 profile、工具权限和运营日志需要分开保存。公开拆解还强调账号登录态、运营目标、Agent Loop、工具审批和会话日志是独立层，不能把它们塞进一次翻页任务里。

## 本次卡死路径

旧实现把浏览器启动、CDP 连接、页面采集、翻页和整理全部放在一个长循环里。初次连接超过 15 秒、浏览器被关闭、`Runtime.evaluate` 超时或页面 WebSocket 失效后，状态仍可能停留在 `collecting`，前端只看到一直运行，用户无法知道是登录、页面还是浏览器故障。

本轮改为有界失败策略：

- 初次 CDP 连接超过 15 秒直接结束本轮并写入 `CDP_UNAVAILABLE`。
- 浏览器进程退出写入 `BROWSER_CLOSED`，保留已采集会话。
- 页面采集连续三次超时写入 `CDP_STALLED`，停止本轮，避免桌宠卡死。
- CDP 断线最多重连三次，超过后写入 `CDP_RECONNECT_FAILED`。
- 每次账号使用独立 profile，切换账号时不会复用上一个账号的浏览器窗口。

## 小狗账号模型

账号档案保存在应用数据目录的 `video/accounts.json`，浏览器 profile 保存在 `%LOCALAPPDATA%\Maltese\video-accounts\<account-id>`。

账号包含以下信息：

- 平台和账号显示名
- 平台昵称或账号标识
- 小狗人设和运营目标
- 登录状态：草稿、等待登录、已就绪、暂停
- 创建时间、最近登录时间、最近运行时间

创建档案不会自动填写手机号、邮箱或验证码。用户在官方页面完成注册或登录，点「我已登录」后，状态才会变为「已就绪」。这是平台账号的正常授权交接，避免把个人凭据写入应用或脚本。

## 自主运营链

当前可执行链路是：

1. 创建小狗账号档案。
2. 打开该账号的独立登录窗口。
3. 用户完成平台注册或登录并确认。
4. 小狗使用该账号的独立 profile 刷推荐流。
5. 采集标题、作者、时长、进度和兴趣信号。
6. 生成小结和运营日志草稿，写入待投递队列。
7. 用户在草稿区确认后再复制或打开官方投稿页。

评论、投稿、直播和关注属于对外操作，默认保留用户点击和官方页面确认。下一阶段可以在相同 Agent Loop 上增加审批队列、每日预算、内容日历和发布结果回写。

## 当前边界

- 小狗账号可以独立刷视频和生成运营草稿。
- 账号注册由用户在平台官方页面完成。
- 运营草稿可预览、复制和打开官方投稿页。
- 自动发布、自动直播和自动关注尚未接入，避免在没有明确内容、受众和平台授权时代表用户发言。
