## 1. 判定口径（本报告实际使用的版本）

基线一律用**主窗口矩形**（物理像素，含 DWM 边框/透明边距；收起态窗口左下角即小狗屏幕位置，见 [pet-overlay-geometry.md](pet-overlay-geometry.md) 不变量 1）。

| 符号 | 定义 |
| --- | --- |
| **R0** | 收起态基线矩形 `(left, top, right, bottom)`，连续 ≥500 ms 不变后采样 |
| **R1** | 浮层/面板**完全展开**且稳定 ≥500 ms 后的矩形（取采样序列里面积最大的稳定矩形） |
| **R2** | 关闭完成、稳定 ≥500 ms 后的矩形 |

| 判据 | 内容 | 容差/阈值 |
| --- | --- | --- |
| **C1 锚定边** | 面板在右 → `R1.left == R0.left`；面板在左 → `R1.right == R0.right`；面板在上 → `R1.bottom == R0.bottom`；在下 → `R1.top == R0.top` | ≤2 px（150% 缩放下 ≤3 px） |
| **C2 回落** | `R2` 的 `left/top/right/bottom` 与 `R0` 逐边比对 | **逐像素相等（0 px）**为目标，允许 ≤2 px |
| **C3 抗累积** | 连续 10 次开合后，第 10 次关闭稳定后的 `R2(10)` 与 `R0` 逐边比对 | ≤2 px，且不得单调增大 |
| **C4 无中间放大帧** | 打开/关闭过程中允许的中间帧 | 80 ms 采样下每个非 `R0`/非 `R1` 矩形驻留 **≤160 ms**（≈2 采样）；对应 30 fps 口径 ≤1 帧（33 ms）不判失败 |
| **C5 可见性** | 主窗口 `IsWindowVisible=False`、矩形为 0×0、窗口消失 | 一律判失败 |
| **C6 方向** | 贴右边缘时面板必须翻到左侧（`R1.left < R0.left` 且 `R1.right ≈ R0.right`），贴左时反之 | ≤2 px |
| **C7 视觉** | 残影 / 裁切 / 空白 / 云朵尾巴指向 / 频闪 | 需 30 fps 录屏或肉眼，本报告**无法判定**（标记未执行） |

**采样精度说明（重要）**：80 ms 轮询只能证明「没有被 80 ms 采样看见的中间矩形」。更细的中间帧由 2 ms 采样覆盖（见 [delivery-verify-2026-11-17.md](delivery-verify-2026-11-17.md) §5：展开页路径曾捕获 16 ms 中间帧，右沿越界 452 px / 下沿越界 42 px，属 C4 允许范围）。因此本报告 C4 一律按 **80 ms 口径**表述，不把「80 ms 未捕获中间帧」当作「零中间帧」。

## 3. 采样方法与「为什么不合成输入」

### 3.1 采样器

- 路径：`%TEMP%\mal-matrix\sample-island-rect.ps1`（全文见 [附录 A](#附录-a-sample-island-rectps1-全文)）
- 能力：`EnumWindows` 按 PID + 精确标题 `Maltese 线条小狗桌面助手` 找主窗口 → 每 `-IntervalMs`（默认 80 ms）读 `GetWindowRect` + `IsWindowVisible`；
  **仅在矩形/可见性变化时写一行**，另每 40 tick（≈3.2 s）写一行 `heartbeat-unchanged` 心跳，用来证明采样器没死、且这段时间矩形没变。
- 只读承诺：只调用 `EnumWindows` / `GetWindowRect` / `IsWindowVisible` / `GetWindowText` / `GetClassName` / `GetThreadProcessId` / `GetDpiForWindow`；
  不 `SetWindowPos`、不 `PostMessage`、不 `SetCursorPos`、不读写应用数据。
- 输出：`rect-<stamp>.csv`（含 `ts_ms, iso, hwnd, visible, L, T, R, B, W, H, kind, other_visible_windows, event, dwell_ms`）+ `rect-<stamp>.log`（人读事件行）。

### 3.2 为什么不用合成输入

任务约束明确「不要用合成鼠标输入操作，避免抢用户输入、污染归因」；且本机用户正在同时使用桌宠（采样窗口里就抓到了真实操作序列），
合成输入会与用户操作混在一起，**无法归因**。因此本轮采取「只读采样 + 被动捕获真实操作」，把需要代操作的格子留成待执行表（§7），
并提供交互式 runner（§8.3）让人 10～15 分钟跑完。

## 6. 为什么 8 格没执行（以及执行须知）

- **不能代操作**：M1/M4/M6/M7/M8/M11 的核心动作是鼠标悬停、右键、拖拽、动画中开气泡；本轮被要求不合成输入，也不改用户设置（闲逛/缩边开关属用户 `localStorage`）。

- **不能判视觉**：M12（残影/裁切/空白）与 M5 的频闪需要 30 fps 录屏；采样器只能给矩形，不能判像素残影。

**执行须知（给操作的人）**

1. 起始状态：设置保持默认（气泡开、剪贴板气泡开），小狗收起、放在屏幕**中左**（M2/M11 再拖到最右）；关掉其它悬浮窗。

3. 打开/关闭的判定点：等**完全展开**（≤500 ms）再松手，关闭后等 420 ms 自动收起 + 再稳 500 ms。
4. 需要录屏的格（M5/M9/M12）：Windows `Win+G` 或 OBS 30 fps，录到「打开那一帧」和「关闭那一帧」。
5. 每格 1 分钟；M1/M2/M11/M3/M6/M8/M9 ≈ 7 分钟，加上录屏与抄表 15 分钟内可完。

## 10. 结论与验收门槛对照

对照 [bug-acceptance-2026-11-17.md](bug-acceptance-2026-11-17.md) §4：

| 门槛 | 结论 |
| --- | --- |
| §4.1-7「至少一台 Windows 实机跑过 B1/B2 主用例，附录屏或截图 + 矩形数值」 | **不满足**：B2 强触发矩阵人工执行 0 格；本报告只有被动序列（4 格几何判据：M2/M3/M5/M6，无录屏） |
